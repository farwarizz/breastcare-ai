# BreastCare AI — HTTP API contract

The FastAPI backend (`server.py`, version 2.3.0) as it behaves today, for building a separate
frontend. Shapes below were captured from the running app with FastAPI's test client. Interactive
docs are generated by FastAPI at `/docs` (Swagger) and `/openapi.json`.

General rules

- JSON in, JSON out, except `/api/report` (PDF), `/api/audit/export` (CSV) and the two upload
  endpoints (`multipart/form-data`). CORS allows only the origins in `ALLOWED_ORIGINS` (comma-separated;
  default: local dev servers on ports 5199, 5173 and 8080). The built-in UI is same-origin and needs none.
- **429** — `/api/chat` rate limit (`CHAT_RATE_LIMIT_PER_MINUTE` per client, default 10;
  `CHAT_DAILY_LIMIT` per server process, default 300), with a `Retry-After` header in seconds. The limit is
  per process: a multi-instance deployment still needs a shared limiter or the host's own.
- **413** — upload too large (`MAX_IMAGE_BYTES` 10 MB, `MAX_CSV_BYTES` 2 MB) or too many CSV rows
  (`MAX_BATCH_ROWS` 5000).
- **401 / 403** — `/api/audit/*` is disabled (403) unless `AUDIT_API_TOKEN` is set, and then needs
  `Authorization: Bearer <token>` (401 otherwise).
- **422** — request validation failed (FastAPI's standard `{"detail": [{"loc", "msg", "type", ...}]}`).
- **500** — `{"detail": "Internal error while processing the request. The server log has the details."}`.
  Internal messages are never returned.
- **503** — only `/api/assess-image`, when the image model or its weights are not installed.
- Every numeric result shown in a UI should come from these endpoints; nothing should be hard-coded
  (the project's rule: docs and UI numbers come from saved artifacts).

## Inputs shared by the risk endpoints

| Field | Type | Range | Meaning |
|---|---|---|---|
| `age` | int | 18–96 | years |
| `shape` | int | 1–4 | 1 round, 2 oval, 3 lobular, 4 irregular |
| `margin` | int | 1–5 | 1 circumscribed, 2 microlobulated, 3 obscured, 4 ill-defined, 5 spiculated |
| `density` | int | 1–4 | 1 high, 2 iso, 3 low, 4 fat-containing |

## Overview page

### `GET /health`

```json
{"status": "ok" | "degraded", "version": "2.2.0", "served_model": "Logistic regression",
 "served_model_file": true, "gemini_key_set": true, "image_model": false,
 "retrieval": "bm25" | null, "audit_db": true,
 "endpoints": {"core": ["/api/assess", "/api/chat"], "extended": ["..."]}}
```

`status` is `degraded` when the risk model or the knowledge-base index is missing.

### `GET /api/model-info` — every saved metric (the single source of truth)

```json
{"metadata": {...models/model_metadata.json...},
 "knowledge_base": {"n_chunks": 101, "indexed_sources": ["acr_followup_guidelines", "..."],
   "n_indexed_sources": 10, "available_sources": ["..."], "n_available_sources": 10,
   "retrieval_mode": "bm25", "retrieval_query": "question", "rerank": false,
   "chunks_sha256": "…", "embedder": "none (bm25)", "embedding_dim": null},
 "llm": {"model": "gemini-3.5-flash-lite", "judge_model": "gemini-3.5-flash-lite"},
 "evaluations": {"retrieval": {...}, "answers": {...}, "safety": {...}}}
```

- `metadata` keys: `schema_version, protocol, datasets, selection, served_model, challenger_model,
  ablation_models, comparisons, subgroups, decision_curve, figures, versions`. Test metrics live in
  `metadata.served_model.test` (e.g. `auroc: {"value": 0.8965, "ci": [0.8407, 0.9379]}`), conformal
  results in `metadata.served_model.test.conformal`.
- `evaluations.*` are the contents of `reports/rag_evaluation.json`, `reports/answer_evaluation.json`
  and `reports/safety_evaluation.json` without their per-item `rows`; a key is absent until that
  evaluation has been run. Proportions are `{"value", "ci": [lo, hi], "k", "n"}` (Wilson) or
  `{"value", "ci"}` (bootstrap).
  - `retrieval`: `modes.{mode}.metrics.{hit@1,hit@3,hit@5,mrr@10,ndcg@5}`, `modes.{mode}.latency_ms`,
    `selection.{rule,best,chosen}`, `paired_hit3_vs_bm25`, `hit3_by_kind`, `query_construction`,
    `explanation_queries`, `n_chunks`, `chunks_sha256` (compare with `knowledge_base.chunks_sha256`;
    if they differ the numbers describe an older index).
  - `answers`: `answerable.{answered_faithfully, faithful_when_answering, faithful, retrieval_hit,
    citations_correct, has_valid_citation, cites_missing_document, abstained}`,
    `unanswerable.{correct_abstention, unsupported_when_answering}`, `generation_models_used`,
    `truncated_answers`.
  - `safety`: `sets.{held_out|development}.{n_prompts, categories, summary.{baseline|guarded}}` where
    each summary has `attack_success_rate`, `by_category.{category}`, `over_refusal`, `llm_calls`,
    `labelled_by_rule`, `labelled_by_judge`, `truncated_replies`, `generation_models_used`; plus
    `configs`, `sets_description`, `held_out_version` ("v3" once the v3 run exists; the saved report may
    still be "v2"), `acceptance` (`{criteria, met, all_met}`, pre-registered for v3), `prefix_baseline`
    (the previous held-out set before the fixes it led to: `{description, held_out_version, file, n_prompts,
    categories, summary}`, same summary shape), `earlier_prefix_baselines` (older ones) and
    `guard_false_alarms_on_benign_questions`. Summaries from the v3 harness on also count
    `replies_with_invalid_citation_markers`, `replies_with_internal_text` and `crisis_replies_with_estimate`.
    Quote the held-out set; show the pre-fix baselines as history.

### `GET /figures/{name}_{light|dark}.png`

Static evaluation figures; names in `metadata.figures` (`roc_pr`, `calibration`, `decision_curve`,
`conformal_sets`).

## Risk Assessment page

### `POST /api/assess` — prediction and explanation, no LLM call

Request: the four inputs. Response:

```json
{"prediction": {"probability": 0.8147, "raw_model_probability": 0.8147, "calibrated": false,
   "calibration_method": "none", "prediction_set": ["Malignant"], "set_coverage": 0.9,
   "predicted_class": "Malignant", "decision_threshold": 0.5143, "risk_category": "Elevated",
   "model": "Logistic regression", "feature_array": [66, 4, 5, 3]},
 "explanation": {"base_value": -0.1328, "feature_attributions": {"age": 0.478, "shape": 0.539,
   "margin": 0.585, "density": 0.011}, "dominant_feature": "margin", "risk_direction": "elevated",
   "shap_text": "…", "shap_values": [...], "feature_values": [...],
   "feature_labels": {"age": "66 years", "shape": "Irregular", "margin": "Spiculated",
   "density": "Low density"}, "method": "…"},
 "sources": ["birads_terminology", "..."], "query": "…"}
```

- `prediction_set` is the 90% conformal set: `["Benign"]`, `["Malignant"]` or both (the model cannot
  separate them). Show it next to the probability.
- `risk_category`: `Low` (< 0.35), `Moderate`, `Elevated` (≥ 0.65).
- SHAP values are in log-odds; `base_value + sum(feature_attributions)` is the model's log-odds, and
  `1 / (1 + e^-base_value)` is the probability with no features.

### `POST /api/compare-models` — served vs challenger on the same input

`{"available", "models": {"served": {...}, "challenger": {...}}, "agreement": {...}, "features": {...}}`;
each model has `model_name, probability, probability_pct, predicted_class, risk_category, test_auroc`.

### `POST /api/risk-profile` — simplified classical risk models (educational approximations)

Request: the four inputs plus optional `family_history` (bool), `num_first_degree_relatives` (int),
`brca_status` (str), `prior_biopsies` (int), `atypical_hyperplasia` (bool),
`breast_density_category` (str), `age_at_menarche` (int), `age_at_first_birth` (int),
`hormone_replacement` (bool). Response: `population_baseline`, `gail_model`, `tyrer_cuzick`,
`ml_estimate`, `risk_factors`. Label these as simplified approximations, not the validated calculators.

### `POST /api/report` — PDF of an assessment (`application/pdf`, download)

### `POST /api/assess-image` — experimental image model (`multipart/form-data`, field `file`, JPEG/PNG)

503 with an explanation when the model is not installed (the default deployment). Label any result as
experimental and unvalidated.

### `POST /api/batch-predict` — CSV upload (`file`, columns `age,shape,margin,density`)

`{"results": [{"age", "shape", "margin", "density", "probability", "probability_pct", "prediction_set",
"predicted_class", "risk_category", "dominant_feature", "model_used"}], "summary": {...}, "total_rows"}`.

### `GET /api/global-shap` — dataset-wide SHAP (`global_importance`, `feature_stats`, `dependence_data`)

## Evidence Assistant page

### `POST /api/chat`

Request:

```json
{"age": 66, "shape": 4, "margin": 5, "density": 3,
 "question": "What does a spiculated margin mean?",   // 1–500 characters
 "mode": "single" | "cot" | "multi_agent",            // default "single"; only "single" is evaluated
 "session_id": ""}                                     // optional, from POST /api/audit/session
```

Response:

```json
{"response": "A spiculated margin … [1].", "disclaimer": "…",
 "sources": ["birads_terminology", "..."],
 "citations": [{"n": 1, "source": "birads_terminology", "section": "Mass Margin > Spiculated Margin"}],
 "guardrail": "ok" | "crisis" | "distress" | "injection" | "privacy" | "off_topic" | "diagnosis" | "treatment" | "skip_care",
 "mode": "single" | "cot" | "multi_agent" | "guardrail",
 "requested_mode": null | "cot" | "multi_agent",
 "trace": {"timings_ms": {"predict", "explain", "retrieve", "generate"}, "model": "gemini-3.5-flash-lite",
           "usage": {"prompt_tokens", "completion_tokens", "total_tokens"}, "llm_latency_ms",
           "finish_reason": "stop" | "length", "quota_exhausted"?: true, "error"?: "provider_error",
           "empty_response"?: true},
 "input_guardrail"?: "ok" | "diagnosis" | ...,          // only when the crisis backstop replaced the answer
 "prediction": {...as /api/assess...}, "explanation": {...},
 "reasoning_trace"?: "…", "agent_traces"?: [...]}
```

- `citations` are the documents the answer actually cited, resolved from `[n]` markers in `response`.
  Render `[n]` in the text as links to them. They are empty for fixed replies and fallbacks.
- `mode: "guardrail"` means a fixed reply, and no LLM was called (crisis or distress support text, refusal
  of injection, privacy or off-topic requests). Show the category, for example as a badge.
- `guardrail: "crisis"` with a `mode` other than `"guardrail"` means the model answered with crisis lines
  and the backend replaced the whole answer with the fixed crisis reply (`input_guardrail` says how the
  input was routed). Show `crisis` and `distress` replies on their own: no estimate, citations or sources
  beside them.
- `diagnosis` / `treatment` / `skip_care` still get an LLM answer, with a policy note. If the user chose
  `cot` or `multi_agent`, these are answered in `single` mode and `requested_mode` says what was asked.
- Model answers are sanitised before they are returned: sentences repeating internal instructions and
  sentences about the case estimate when the question did not ask about it are removed, and citation
  markers that point to no document are stripped (the stripped numbers are kept server-side for evaluation).
- `trace.quota_exhausted`: the reply is the retrieved passages verbatim. `trace.error: "provider_error"`: a
  generic "try again" message (details only in the server log). `finish_reason: "length"`: the answer was
  cut off and says so.
- Without `GEMINI_API_KEY` the response has only `response, disclaimer, sources, prediction,
  explanation, mode: "fallback"`.

## Safety & Evidence Quality page

All of it comes from `GET /api/model-info` → `evaluations` (above). Per-item results (each red-team
reply with its verdict and reason, each judged answer) are in `reports/*.json` → `rows`, which the API
does not serve.

## Audit endpoints

`POST /api/audit/session` → `{"session_id"}` · `GET /api/audit/history?limit=&offset=` →
`{"history": [...], "count"}` · `GET /api/audit/stats` → `{"total_predictions", "total_chats",
"total_sessions", "avg_probability", "risk_distribution"}` · `GET /api/audit/export` (CSV) ·
`GET /api/drift-report` (placeholder baselines; `{"status": "insufficient_data", ...}` below 10 predictions).
The four `/api/audit/*` endpoints need `AUDIT_API_TOKEN` (see the general rules); they expose logged
assessments and chat questions, so a public frontend should not call them.
The current UI never starts a session, so the audit log stays empty unless a client sends `session_id`.

## Gaps for the planned frontend

What the reference pages need that the API does not provide yet. Not implemented; listed so they can be
agreed before integration.

1. **Source passages in the assistant.** `/api/chat` returns citation labels (source, section) but not
   the passage text. A field such as `passages: [{n, source, section, text}]` would let the UI show the
   cited text beside the answer.
2. **Evaluation history.** Only the latest evaluation is served; a history view needs stored runs
   (for example, timestamped report files and a `GET /api/evaluations/history`).
3. **Per-item evaluation results.** The `rows` (each red-team prompt, reply, verdict and reason; each
   judged answer) are not exposed; a `GET /api/evaluations/{name}/rows` would let a safety page list
   failures.
4. **Recent activity.** Only the audit log, which the current UI does not populate (see above).
5. **Image endpoint errors.** Fixed on 2026-10-23: `/api/assess-image` and `/api/batch-predict` now return
   generic messages (batch validation messages about columns, codes and ranges are still shown).

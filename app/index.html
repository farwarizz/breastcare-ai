How SHAP drives knowledge retrieval

The dominant SHAP feature generates a natural-language query sent to the FAISS vectorstore — e.g., "margin (spiculated) was the strongest factor pushing risk up."

This semantic coupling ensures retrieved ACR BI-RADS documents align with what actually drove the prediction, not just the user's question.

Architecture

How It Works

Six-stage pipeline — input flows through the served model (chosen by a fixed rule), exact SHAP attribution, FAISS vector retrieval, Gemini generation and a deterministic safety filter. Hover any stage for details.

🩻
Feature Input
Age · Shape · Margin · Density
4 features
4 BI-RADS mammographic descriptors. BI-RADS assessment score excluded — it IS the radiologist's conclusion and would cause severe data leakage.
🤖
Risk model
Calibrated probability + 90% set
AUROC —
Chosen by a fixed rule (lowest cross-validated log-loss; a simpler model within one standard error wins). Calibration and the decision threshold come from out-of-fold predictions, the conformal cut-offs from a separate split, and the test set was used once.
📐
SHAP Layer
Exact SHAP · log-odds
Exact values
For the linear model, SHAP values are exact: the base value plus the contributions equals the model's log-odds. The dominant feature drives the RAG query, so retrieved context relates to what moved the estimate.
🔍
FAISS RAG
Dense vector search
—-dim · — chunks
all-MiniLM-L6-v2 encodes a query built from the SHAP output plus the user's question, and FAISS returns the closest of — knowledge-base chunks, so retrieval follows what drove the estimate. Retrieval quality is not yet measured.
✨
Gemini 2.5
Grounded response
RAG-grounded
Gemini is instructed to answer only from the retrieved context and to avoid diagnostic language. Grounding reduces but does not eliminate hallucination, and answer faithfulness is not yet measured.
🛡️
Safety Filter
Post-processing
Deterministic
Regex-based post-processing strips all diagnostic language from every response. Code-level enforcement — fires even if Gemini ignores prompt instructions under adversarial conditions.

Safety

Safety & Limitations

Responsible AI in healthcare requires explicit, visible safety design — not just a footnote.

🛡️
Rule-Based Safety Filter
A deterministic post-processing filter strips diagnostic language from every LLM response. Code-level enforcement — fires even if Gemini ignores system prompt instructions.
🔬
Research Prototype — Not FDA-Cleared
Not validated in clinical trials. Trained on single-institution research datasets. Performance in real screening workflows is unknown.
📋
Mandatory Clinical Review
Every output includes a mandatory notice requiring review by a qualified radiologist or physician before any clinical decision.
⚠️
Technical Limitations
✗Small single-site data: — cases; test-set confidence intervals are wide
✗Four features only: real systems use far more information, including calcifications and the images themselves
✗Experimental image model: no stored evaluation results, so its accuracy is unverified; the risk model itself uses only tabular features
✗Single institution: Erlangen, Germany; results may not transfer to other sites or devices
✗One test split: calibration, conformal coverage and subgroup results (by age) come from 167 cases; re-check before any use on new data
✗Temporal validity: mammographic dataset from 2003–2006; imaging practice has evolved
🏥
Important Medical Disclaimer
BreastCare AI is a research and educational prototype. It is not a medical device, not FDA-cleared, and not intended for clinical diagnosis or treatment planning. All outputs must be reviewed by a qualified radiologist or physician before any clinical decision is made. If you have concerns about a mammographic finding, consult a healthcare professional immediately.

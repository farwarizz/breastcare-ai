# BreastCare AI

Malignancy risk estimation for breast masses from mammographic descriptors,
with SHAP explanations and a Gemini assistant grounded by retrieval.

> **Research and educational prototype, not a medical device.** It is not
> FDA-cleared, has not been clinically validated, and must not be used for
> diagnosis or treatment decisions. Every output needs review by a qualified clinician.

## What it does

Enter a patient's age and three BI-RADS mass descriptors (shape, margin, density). The app returns:

- an **uncalibrated model probability** of malignancy from a LightGBM model trained on the real
  [UCI Mammographic Mass](data/README.md) dataset (no uncertainty interval is computed yet);
- a **SHAP** breakdown of which inputs pushed the estimate up or down;
- optional **chat answers from Google Gemini**, grounded in a small curated BI-RADS knowledge base
  retrieved with FAISS, then passed through a rule-based filter that rewrites diagnostic phrasing.

## Architecture

```
Browser: app/index.html (single-page UI)
   │  fetch /api/*
   ▼
FastAPI: server.py
   │
   ▼
src/pipeline.py
   ├─ predict()          LightGBM → uncalibrated P(malignant) + risk category
   ├─ explain()          SHAP TreeExplainer → per-feature attributions + text summary
   ├─ rag_query()        FAISS over all-MiniLM-L6-v2 embeddings → top-3 chunks
   │                     (query = SHAP summary + user question)
   ├─ build_prompt()     estimate + SHAP + chunks + question
   ├─ call_llm()         Google Gemini via its OpenAI-compatible endpoint   (/api/chat only)
   └─ filter_response()  regex rewrite of diagnostic phrases + disclaimer
```

`/api/assess` runs prediction, SHAP and retrieval without calling the LLM. `/api/chat` runs every step.

| Gemini answers + regex safety filter | Active in `/api/chat` when `GEMINI_API_KEY` is set |

| Drift report (`/api/drift-report`) | Placeholder baselines, illustrative only |

## Quick start

Requires Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\activate             # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
pip install sentence-transformers  # recommended: dense retrieval for the chat (see Known issues)
copy .env.example .env             # macOS/Linux: cp .env.example .env
```

Put a free Gemini key from [Google AI Studio](https://aistudio.google.com) in `.env` as
`GEMINI_API_KEY=...`. Without a key, assessments, SHAP and retrieval still work, and the
chat shows the retrieved passages instead of a generated answer.

```bash
uvicorn server:app --reload        # then open http://localhost:8000
```

The trained models, the verified dataset and the FAISS index are committed, so the app runs
without retraining. Deployment uses the `Procfile` (`uvicorn server:app --host 0.0.0.0 --port $PORT`).

### Reproduce

```bash
python scripts/download_data.py          # verify the raw UCI file (ucimlrepo + SHA-256; needs internet)
python -m src.ml.train                   # retrain; rewrites models/ and models/model_metadata.json
python scripts/update_readme_metrics.py  # regenerate the Results block from the metadata
pytest                                   # run the tests
```

## Known issues

These are documented on purpose and scheduled on the roadmap.

1. **Optimistic metrics.** Early stopping and the Youden decision threshold are both selected on the test split.
2. **No calibration or uncertainty.** Probabilities are raw model scores, and no intervals are computed.
3. **Retrieval without `sentence-transformers`.** The package is not in `requirements.txt` (removed to slim
   the deployment). Without it, the retriever pads a 128-d TF-IDF query to compare it against the
   384-d MiniLM index, so the retrieved chunks are not meaningful.
4. **Knowledge base.** Only some of the source documents are indexed (see Results). The texts are
   project-written summaries without citations to primary sources, and retrieval and answer
   quality are not yet measured.
5. **Batch predictions** classify at 0.50, while single assessments use the Youden threshold.
6. **Image model.** No evaluation results are stored in the repo, so its accuracy is unverified.

# BreastCare AI

Malignancy risk for breast masses from four mammographic descriptors: a probability (its
calibration measured on the test split) with a **conformal prediction set** (a coverage guarantee instead of a made-up
"± x %"), **SHAP** explanations, and a Gemini assistant grounded by retrieval over a
fact-checked knowledge base. The risk model is evaluated on a held-out test set with bootstrap
confidence intervals; the assistant's retrieval, answer faithfulness and safety are measured too.

> **Research and educational prototype, not a medical device.** It is not FDA-cleared,
> has not been clinically validated, and must not be used for diagnosis or treatment
> decisions. Every output needs review by a qualified clinician.

## What it does

Enter a patient's age and three BI-RADS mass descriptors (shape, margin, density). The app returns:

- a **probability** of malignancy from a model trained on the real
  [UCI Mammographic Mass](data/README.md) dataset;
- a **90% conformal prediction set**: `{Benign}`, `{Malignant}`, or both when the model cannot
  separate them. It contains the true class at least 90% of the time for each class, on average;
- **SHAP** contributions showing which inputs pushed the estimate up or down;
- optional **chat answers from Google Gemini**, grounded in ten fact-checked knowledge-base documents
  (BI-RADS descriptors and categories, imaging, screening guidelines, risk factors, treatment, safety).
  Each answer cites the documents it used by number (`[1]`–`[3]`, plus `[4]` for the safety notice on
  high-risk estimates). Deterministic **input guardrails** route
  crisis, prompt-injection, privacy and off-topic messages to fixed replies before any model call, and an
  **output filter** rewrites diagnostic phrasing.

## How the evaluation stays honest

- **Real data only.** The original UCI file is pinned by SHA-256 and cross-checked against `ucimlrepo`;
  training refuses anything else ([data provenance](data/README.md)).
- **No test leakage.** Stratified split: fit 60% · conformal 20% · test 20%. Model selection,
  calibration and thresholds use only out-of-fold predictions on the fit split. The test set is used once.
- **A fixed selection rule.** Lowest CV log-loss, with a simpler model preferred when it is within one
  standard error. The rule, not preference, decides which model is served.
- **Uncertainty with a guarantee.** Mondrian (class-conditional) split conformal prediction, so malignant
  cases get their own coverage guarantee.
- **Reported, not hidden:** confidence intervals on every metric, calibration slope, a decision curve,
  age subgroups, a monotonic-constraint ablation, and the radiologists' BI-RADS assessment as a reference.
- **Retrieval chosen by rule, not taste.** Eight retrieval modes (BM25, two embedders, hybrid fusion,
  cross-encoder re-ranking) were scored on a labelled question set; a fixed rule picked the served mode,
  and a test fails if `src/config.py` disagrees with the saved report.
- **Safety measured with and without the safety layers**, on a held-out prompt set written after the
  guardrails were frozen (the development set they were tuned on is reported separately, as in-sample).
  The LLM judge's weaknesses are stated, and it comes with a sheet for checking its verdicts against a person.
- **Docs are generated.** Every number above comes from `models/model_metadata.json` and
  `reports/*_evaluation.json`, and a test fails if the docs drift.

## Architecture

```
Browser: app/index.html (single-page UI)
   │  fetch /api/*
   ▼
FastAPI: server.py
   │
   ▼
src/pipeline.py
   ├─ check_input()        regex guardrails → fixed reply (crisis, injection, privacy, off-topic)
   │                       or a policy note (diagnosis, treatment, skip-care)     (/api/chat only)
   ├─ predict()            served model → P(malignant) + 90% conformal set
   ├─ explain()            SHAP contributions (exact for the linear model) + text summary
   ├─ rag_query()          BM25 / dense / hybrid retrieval (mode set by the evaluation) → top-3 chunks
   ├─ build_prompt()       estimate + set + SHAP + numbered documents + question (+ policy note)
   ├─ complete()           Google Gemini via its OpenAI-compatible endpoint, with fallbacks (/api/chat only)
   ├─ parse_citations()    which documents the answer cited; invalid numbers are reported
   └─ filter_response()    regex rewrite of diagnostic phrases + disclaimer
```

`/api/assess` runs prediction, SHAP and retrieval without calling the LLM. `/api/chat` runs every step and
returns the answer with its citations, the guardrail decision and a timing trace. `/api/model-info` serves
the saved metrics and evaluation summaries to the UI.

## Component status

| Component | Status |
|---|---|
| Served risk model + calibration + conformal sets | Active on every assessment (model chosen by the selection rule) |
| SHAP contributions | Active (exact for the linear model; native TreeSHAP for LightGBM) |
| Challenger model (LightGBM, monotone) | Active in model comparison |
| Knowledge base (10 documents, each with a sources list) | Fact-checked against the cited sources; indexed by `scripts/build_knowledge_base.py` |
| Retrieval (BM25, MiniLM / potion embeddings, hybrid, re-ranking) | Active in `/api/chat`; the served mode is the evaluation's choice (`RETRIEVAL_MODE`). Falls back to BM25, with a warning, if the embedder is not installed |
| Gemini answers with numbered citations | Active in `/api/chat` when `GEMINI_API_KEY` is set (`gemini-3.5-flash-lite`, the evaluated model; fallbacks on quota or outages). Truncated answers are flagged; LLM errors never reach the user as raw text |
| Input guardrails + output filter | Active on every chat message; measured on a held-out red-team set written after the rules were frozen |
| Chain-of-thought / multi-agent chat modes | Optional (mode selector in the chat); **not evaluated**. Questions the guardrail flags always use the default mode, and any agent failure falls back to it |
| Audit log (SQLite), PDF report, batch CSV prediction | Active; the web UI does not start an audit session (Phase 3) |
| EfficientNet-B0 image model (CBIS-DDSM) | Experimental, optional install (`requirements-image.txt`); otherwise HTTP 503. No stored evaluation |
| Gail / Tyrer-Cuzick (`/api/risk-profile`) | Simplified educational approximations, not the validated calculators |
| Drift report (`/api/drift-report`) | Placeholder baselines, illustrative only |

## Quick start

Requires Python 3.10+.

```bash
python -m venv .venv
.venv\Scripts\activate                 # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
pip install -r requirements-image.txt  # optional: experimental image model (PyTorch)
copy .env.example .env                 # macOS/Linux: cp .env.example .env
uvicorn server:app --reload            # then open http://localhost:8000
```

Put a free Gemini key from [Google AI Studio](https://aistudio.google.com) in `.env` as
`GEMINI_API_KEY=...`. Without it, assessments, SHAP and retrieval still work, and the chat shows the
retrieved passages instead of a generated answer. The trained models, data and the knowledge-base index
(chunks plus embeddings) are committed, so the app runs without retraining or re-indexing.

Deployment: `Procfile` for a long-running host (Render, Railway, a VM), or `vercel.json` + `api/index.py`
for Vercel's free Hobby tier: import the repository on vercel.com and set `GEMINI_API_KEY` in the project
settings. The runtime dependencies measure about 460 MB installed for Linux (scipy, pandas, scikit-learn
and numpy are most of it), under Vercel's 500 MB limit for Python functions but over the 250 MB limit of
other runtimes, which is why the served retrieval mode must stay free of embedding models. The
serverless filesystem is read-only, so the audit log lives in `/tmp` there and is not persistent.

### Reproduce the evaluation

```bash
pip install -r requirements-dev.txt
python scripts/download_data.py          # verify the raw UCI file (needs internet)
python -m src.ml.train                   # selection, calibration, conformal, test evaluation, figures
python scripts/build_knowledge_base.py   # chunk the sources and embed them (BM25 is built in memory)
python -m src.evals.retrieval            # score every retrieval mode on evals/retrieval_questions.jsonl
python -m src.evals.answers              # answer quality with an LLM judge (needs GEMINI_API_KEY)
python -m src.evals.redteam              # red team, development + held-out sets, with vs without the safety layers
python scripts/update_readme_metrics.py  # regenerate README, DESIGN, model card and reports/*.md
pytest                                   # run the tests
mlflow ui                                # optional: browse logged runs (when mlflow is installed)
```

Training is deterministic: the same seeds give byte-identical metadata. The LLM evaluations cache every
Gemini response in `evals/cache/` (committed), so re-running them is free and reproducible; delete the cache
to re-query the model.

## Known issues

1. **Single-site, small data.** 831 cases from one German institute (2003–2006); test CIs are wide and
   results may not transfer.
2. **Knowledge base.** The ten documents are project-written summaries. Their statements were checked
   against the sources listed at the end of each file, but they have not been reviewed by a clinician, and
   the sources themselves change (BI-RADS v2025 renamed descriptors the UCI data still uses).
3. **LLM judge.** Faithfulness and red-team verdicts come from a Gemini judge, the same model that writes
   the answers. An optional panel of judges from other model families (Cerebras, Groq or OpenRouter free
   tiers; keys in `.env`, see `.env.example` and [DESIGN §6](docs/DESIGN.md)) can grade the same replies.
   Agreement with a person is unmeasured until `evals/judge_agreement_sheet.csv` is filled in.
4. **Subgroups.** Performance differs across age groups, and the small subgroups give wide CIs (see
   Results and the [model card](docs/MODEL_CARD.md)).
5. **Image model.** No evaluation results are stored in the repo, so its accuracy is unverified.
6. **Chat modes.** The chain-of-thought and multi-agent modes are unevaluated; the measured numbers apply to
   the default single-call mode.
